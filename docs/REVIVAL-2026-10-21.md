## Useful code slice

The existing landing page's waitlist awaited its server function without an
error handler. Network or disk failure left its button disabled indefinitely.
The navigation also linked to `#join`, which did not exist.

The repair adds a real join anchor, immediate duplicate-submit protection,
loading announcements, retryable failure with the original email retained,
confirmed-success feedback, and stale-feedback clearing when editing. The form
identifies the product as in development for adults 18+, with a waitlist rather
than an account signup. Keyboard focus and reduced-motion support are visible;
320/390/768/1280px widths were exercised without horizontal overflow.

The original server function, JSONL storage format, authentication, moderation,
age gate and location contracts are unchanged. Storage remains single-host and
append-only; a lost response after a successful write can still lead to a duplicate
entry on retry. No claim of database-backed waitlist persistence is made.

## Follow-up: strict server type checking

All five prior errors came from missing Bun declarations. Following
[Bun's official TypeScript guide](https://bun.com/docs/typescript), the backend
now pins `@types/bun` 1.3.14 and includes `bun` in compiler types. This exposed
an overly permissive local `ChatServer.upgrade` declaration; it now uses
`Pick<Bun.Server<{ userId: string }>, "upgrade">`, matching the existing
`server.upgrade(req, { data: { userId } })` call. These are type-only changes;
authentication, socket behavior and database contracts were not changed.

CI now invokes `tsc` directly and fails on every error, removing the old error
allowlist. Frozen-lockfile installation, production build, zero-error type-check
and the browser regression suite all passed locally after this change.

Local database feasibility was checked without downloads or configuration changes:
`psql`, `postgres`, `initdb`, and `pg_ctl` are absent from PATH, standard
Postgres installation directories are absent, and Docker's local image inventory
is empty. The runbook requires Postgres + PostGIS + citext; `src/db.ts` uses
Neon's HTTP driver. No ready disposable database stack is installed.
`DATABASE_URL` remains an integration-test blocker; no production secrets were
requested or used. Flutter/Dart remain unavailable.

The branch is pushed at
https://github.com/yaussyross/BEEF/tree/fix/waitlist-recovery .
